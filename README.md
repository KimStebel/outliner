# Outliner

A nested to-do list for the browser — Workflowy-shaped, but smaller and faster.
Mobile-first; wider-screen affordances come later.

## Stack

- **Svelte 5** (runes) + **TypeScript** (strict, `noUncheckedIndexedAccess`)
- **Vite 8** dev server and build
- **Vitest** for the model/ops layer
- **Prettier** (`prettier-plugin-svelte`) for formatting

No UI framework and no rich-text editor dependency. Each list row is its own
`contenteditable`, which keeps caret and focus control in our hands — that
control is most of this app.

## Setup

Node 22 is installed via nvm and symlinked into `~/.local/bin` so it resolves in
non-interactive shells (`~/.bashrc` is not sourced there):

```sh
nvm install 22
ln -sf ~/.nvm/versions/node/v22.*/bin/{node,npm,npx} ~/.local/bin/
npm install
```

`npm run dev` serves on **port 8080**, bound to `0.0.0.0`, so it is reachable
from outside this VM as well as from a phone on the same network. The port is
`strictPort`, so a clash fails loudly rather than silently moving to 8081 and
landing on a port nothing forwards to. `allowedHosts: true` accepts any `Host`
header, so reaching the VM by hostname, alias, or tunnel works — note that this
turns off Vite's DNS-rebinding protection, so it suits a trusted network. It is
a dev-server setting only and has no effect on `build` or `preview`.

Test on a real phone where you can — touch gestures, momentum scrolling, and
virtual-keyboard behaviour are not faithfully reproduced by desktop device
emulation. `npm run e2e` drives its own preview server on 4173 and is
unaffected by the dev port.

## Installing it (PWA)

The production build ships a web app manifest and a service worker, so the app
installs to a home screen and works with no network. Everything it needs is
precached, and the document already lives in `localStorage`, so there is
nothing to sync.

The service worker is only registered in a production build — one in front of
the dev server would serve stale modules and fight HMR. To try it:

```sh
npm run build && npm run preview   # also port 8080
```

**It needs a secure context.** Browsers refuse to register a service worker on
plain `http://` to a LAN address, so over `http://<vm-ip>:8080` the app runs
normally but cannot be installed and will not work offline. Any of these fix
it:

- Serve the build over https (a tunnel, or any static host).
- Open it on the host machine at `http://localhost:8080`, which counts as
  secure.
- For testing on a phone, add the origin to
  `chrome://flags/#unsafely-treat-insecure-origin-as-secure`.

`sw.js` is generated at build time by `build/sw-plugin.ts` rather than written
by hand, because the precache list has to name the real content-hashed
filenames. The cache name is derived from that list, so any asset change
produces a new cache and the old one is deleted on activation. Icons are
generated by `npm run icons` and committed, so a normal build needs no browser.

## Deployment

Live at **https://outliner.stebel.kim**, served by Caddy in Docker.

```sh
npm run deploy   # build, rsync, restart Caddy
npm run smoke    # verify the deployed site
```

The build happens locally and `dist/` is rsynced to the server, so the server
needs no Node toolchain and a deploy is just a file copy. Caddy obtains and
renews the certificate itself; `deploy/Caddyfile` and
`deploy/docker-compose.yml` are the whole server config.

Two things worth knowing about this particular box:

- **Everything lives under `/home/outliner`, not `/opt`.** Docker here is the
  Canonical snap, and snap confinement grants it the `home` interface only —
  from `/opt` the CLI cannot read the compose file and the daemon cannot
  bind-mount the site directory. It fails with a confusing "no configuration
  file provided".
- **The `caddy-data` volume holds the certificates.** Deleting it forces
  re-issuance on the next start, which will hit Let's Encrypt rate limits if
  it happens repeatedly.

Caching is split so deploys actually reach people: hashed files under
`/assets/` are immutable for a year, while `/`, `/sw.js` and the manifest are
`no-cache`. If the shell or the worker were cached, a deploy would keep
serving the previous build indefinitely.

Credentials come from `prod-env` in the project root, which is gitignored:

```
ip: <address>
user: <user>
password: <password>
```

## Architecture

**Flat document model.** Items live in a `Record<ItemId, Item>` with ordered
`children` arrays, not as nested objects — indent, outdent, move, and
delete-subtree then touch only a couple of records instead of rebuilding a tree.
Rendering flattens the visible tree into an array of `(id, depth)` rows, which
is also the shape windowing would need if lists get large enough to warrant it.

**Ops layer.** Every mutation goes through an operation that can produce its own
inverse, feeding an app-level undo stack. This is load-bearing rather than
optional polish: per-item `contenteditable` means the browser's native undo does
not span structural edits, and a mis-triggered swipe deletes a whole subtree.

**Journalled inverses, not hand-written ones.** Rather than writing an undo for
each op, every op runs inside a `Tx` (`tx.ts`) that snapshots the _before_ image
of each record it touches. The inverse of any op — however many records it
rewrites — is then just "put these records back". Flat records keep each journal
entry small enough to produce on every keystroke.

**Total ops.** An operation that cannot apply (outdent at the top level, indent
of a first child) is a no-op returning `null` rather than an error, so the UI can
bind keys without pre-checking. No-ops record no history and, importantly, leave
the redo stack intact.

### Layout

| File            | Role                                                        |
| --------------- | ----------------------------------------------------------- |
| `model.ts`      | Types, plus pure tree/visible-order queries. No mutation.   |
| `tx.ts`         | Change journalling, revert/reapply, coalescing of changes.  |
| `ops.ts`        | Editing semantics. Takes a `Tx`, returns a caret or `null`. |
| `store.ts`      | `DocStore`: owns doc, caret, and undo/redo stacks.          |
| `persist.ts`    | Versioned envelope and a validating loader.                 |
| `storage.ts`    | Debounced, typed `Storage` wrapper.                         |
| `test-utils.ts` | Outline notation (`a` / `  b` / `> collapsed`) for tests.   |

Nothing below `store.ts` imports Svelte, so the whole core is testable in plain
Node. `editor.svelte.ts` is the only seam: it wraps the `Doc` in `$state`, and
because ops mutate records in place, Svelte's deep proxy invalidates only the
fields actually touched. Typing changes `item.text`, which no layout code reads,
so a keystroke does not recompute the row list.

### The UI layer

| File                 | Role                                                  |
| -------------------- | ----------------------------------------------------- |
| `editor.svelte.ts`   | Wraps the doc in `$state` and hands it to the store.  |
| `caret.ts`           | DOM selection <-> character offsets; line geometry.   |
| `Outline.svelte`     | Renders rows; owns all key, input and paste handling. |
| `Row.svelte`         | One row: bullet plus its `contenteditable`.           |
| `KeyboardBar.svelte` | Indent/outdent docked above the on-screen keyboard.   |
| `welcome.ts`         | The first-run document.                               |

Three things carry the weight here:

**The editable's text is never interpolated in the markup.** `Row.svelte` writes
it with an effect, and only when it diverges from the model. If Svelte owned the
text node it would replace it on every keystroke and destroy the caret; writing
only on divergence makes typing a no-op while still letting undo, merge and
paste land.

**Events are delegated to the container**, so adding a row costs no listeners
and handlers can find their row from `data-item-id`.

**Arrow keys consult geometry, not offsets.** Inside a row whose text wraps, the
browser should keep moving the caret and we only take over at the real first or
last visual line — an `offset === 0` test would jump rows from the middle of a
wrapped line.

**The keyboard bar is positioned against the visual viewport.** `position:
fixed` resolves against the _layout_ viewport, which does not shrink when the
keyboard opens, so a bar pinned to `bottom: 0` ends up behind the keyboard. The
bar instead sits at the bottom of a click-through wrapper whose height tracks
`visualViewport.offsetTop + height`. Its buttons act on `pointerdown` with the
default suppressed: allowing the default would move focus to the button, blur
the row, close the keyboard, and unmount the bar before a `click` could ever
arrive.

### Editing semantics worth knowing

- **Enter** splits at the caret. At offset 0 of a non-empty item it pushes the
  line down (empty sibling above, caret stays). On an item with _visible_
  children the tail becomes the new first child, since the children belong to
  the head.
- **Shift-Tab** adopts any following siblings as children. Without that, outdent
  would silently reorder the document on screen.
- **Backspace at offset 0** merges into the previous _visible_ row, children and
  all. Merging a first child into its parent leaves the children in the slot the
  item vacated, so the following siblings keep their place; otherwise they are
  appended to the destination, which is the deepest row before this one and so
  preserves document order. The destination is expanded if it adopts children,
  since dropping them into a collapsed item would look like deletion.
- **Typing coalesces** into one undo step per item within a 600 ms window, so
  undo is not per-character. A structural edit or a caret move breaks the step.
- The document is never left empty; deleting the last item creates a fresh one.
- **Pasting multi-line text makes multiple rows**, in one undo step. A row holds
  one line by definition, so flattening the breaks would silently discard the
  structure that was just pasted. Paste is always intercepted and reduced to
  `text/plain`.
- **Tapping below the list** appends a sibling of the last row — the same thing
  pressing Enter there would do.
- **Long-press anywhere on a row to drag it** on touch, so the small bullet is
  not the only handle. The hold is 400ms — under the ~500ms at which phones
  start selecting text, so the drag wins that race — and any movement before it
  elapses cancels it, leaving scrolling and swipe-to-delete untouched. A row
  that is currently being edited is exempt: there a hold still means "select
  this text", and its bullet remains the way to drag it.
- **Drag a bullet to move an item**, children included. Vertical travel picks
  the gap between rows; horizontal travel picks the depth, which is what makes
  a drag able to re-parent rather than only reorder. The depth is clamped to
  what the neighbours allow: at most one level deeper than the row above (there
  is no intermediate item to adopt you), and never shallower than the row below
  (which would leave that row under a parent it does not belong to). Moving an
  item into its own subtree is refused.
- **Bare URLs, `www.` hosts and email addresses become links.** The rendered
  characters stay identical to the stored ones — links are decoration, not
  substitution — because every caret offset is an index into `item.text`. Only
  `http`, `https` and `mailto` are allowed through; the scheme is checked by
  URL parsing, so a `javascript:` href can never reach the document. A URL
  typed just now becomes a link when the row loses focus.
- **Markdown import** (header button) understands heading level and list
  indentation as nesting, and also plain indented text. Items are appended, so
  an import can never destroy what is there, and the whole thing is one undo
  step. Inline syntax is kept verbatim: rows store what you see, so `**bold**`
  and `[label](url)` stay as written — the URL inside the latter is still
  clickable. Task markers `[ ]` / `[x]` are kept as text, since there is no
  done state to map them onto yet.
- **Tap a row's dot to zoom into it**: the view re-roots on that item, its
  children render at depth 0, and a breadcrumb trails back out. Escape zooms
  out one level. The fold chevron and the zoom dot are deliberately separate
  controls — one tap cannot mean two things, and both double as drag handles.
  While zoomed, navigation, Backspace-merge and outdent all stop at the zoom
  boundary rather than quietly acting on rows that are off screen.
  The zoom is not persisted: a stored zoom could point at an item deleted
  elsewhere, and opening into an unexpected subtree is worse than starting at
  the top. The zoomed item's title is read-only; zoom out one level to edit it.
- **Collapse all** in the header folds every parent at once, and turns into
  expand-all once everything is folded — a collapse-only button would leave no
  way back but opening each row by hand. It is one undo step, and records
  nothing when there is nothing to change.
- **Tap a bullet to fold or unfold** its children. A parent's bullet is a
  chevron — pointing down when open, right when folded — so the state is
  readable at a glance; a leaf keeps a plain dot, since a chevron there would
  advertise an action that does not exist. The bullet occupies a fixed-width
  slot either way, so a parent's text and a leaf's text at the same depth
  still start at the same x.
- **Indent and outdent on mobile** come from a bar docked above the keyboard; a
  phone keyboard has no Tab key, so there is no other way to nest. It shows
  whenever a row is focused on a touch device, and its buttons disable
  themselves when the operation would be a no-op.
- **Swipe a row right to delete it and its children.** The gesture locks
  direction after 8px and only claims clearly rightward travel, so vertical
  scrolling is untouched; it commits past 35% of the row's width. Mouse drags
  are ignored, since inside a row those are text selection.
  **Ctrl/Cmd-Enter** does the same from a keyboard, so deleting a subtree is
  not touch-only. Undo is the header button or Ctrl/Cmd-Z.
- **After a delete the caret moves to the row _below_** the deleted subtree, at
  its start, so the list closes up under the caret and editing carries on
  downwards. It falls back to the end of the preceding row only when nothing
  follows. Note this cannot use `nextVisible`: for a parent that returns its
  own first child, which is inside the subtree being deleted.
- **Deleting by swipe does not move focus.** Focusing a neighbouring row would
  pop the keyboard open over a list the user was only tidying. The keyboard
  shortcut does keep the caret, because there the user is demonstrably typing.

`contenteditable="plaintext-only"` is used where supported, but it is
feature-detected rather than assumed: an unrecognised value maps to `inherit`,
which would leave rows _not editable at all_. The fallback is `true` plus our
own paste interception and suppression of the bold/italic/underline shortcuts.
